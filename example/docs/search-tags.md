## 태그

글의 front matter 에 `tags` 를 쓰면 글 위의 메타 정보에 태그 링크가 생기고, 링크를 누르면 태그 페이지의 해당 구역으로 이동합니다.

```yaml
---
layout: post
title: "글 제목"
tags: [접근성, 가이드]
---
```

태그 페이지는 `tags` 레이아웃으로 만듭니다. 글뿐 아니라 `tags` 가 있는 일반 페이지(이 문서처럼)도 함께 모읍니다.

```yaml
---
layout: tags
title: 태그
permalink: /tags/
---
```

## 검색

검색 페이지는 `search` 레이아웃으로 만듭니다. 만들고 나면 헤더에 **검색** 버튼이 자동으로 생깁니다.

```yaml
---
layout: search
title: 검색
permalink: /search/
search: false
---
```

- 빌드할 때 `/assets/search-index.json` 을 만들고, 브라우저에서 이 파일 하나만 읽어 검색합니다. 외부 서비스나 별도 서버가 필요 없습니다.
- 공백으로 나눈 단어가 모두 들어 있는 글을 찾습니다. 한국어는 단어 중간(예: "접근" → "접근성")도 찾습니다.
- 태그 칩으로 결과를 좁힐 수 있고, 주소(`?q=…&tag=…`)로 결과를 공유할 수 있습니다.
- 검색 대상에서 빼려면 페이지 front matter 에 `search: false` 를 씁니다.
- 일반 검색은 본문을 글마다 앞의 3000자까지만 색인합니다. `_config.yml` 의 `krds.search.max_chars` 로 바꿉니다.

### 문장으로 찾기

질문처럼 문장으로 적어도(예: "첨부 파일에 바이러스가 있는지 검사할 수 있나요?") 가까운 내용을 찾아 검색 결과 아래의 **질문과 가까운 내용**에 보여 줍니다. 단어가 모두 들어 있는 글이 없을 때, 또는 네 단어 이상의 문장일 때 나타납니다. 한두 단어만 넣는 일반 검색은 그대로입니다.

- 글의 소제목 단위로 찾아 `글 제목 › 소제목` 링크와 일치한 부분을 보여 주고, 링크를 누르면 그 소제목으로 이동합니다.
- 모델이나 외부 서비스 없이 글자 두 개씩 겹치는 정도에 희귀도를 곱해 점수를 냅니다. "…할 수 있나요?"처럼 조사와 어미가 붙어도 찾고, 새로 내려받는 파일이 없습니다.
- 태그로 좁히면 그 태그가 있는 글 안에서만 찾습니다.
- **답을 문장으로 만들어 주지는 않습니다.** 관련 있어 보이는 부분을 찾아 줄 뿐이라 정확한 답이 아닐 수 있습니다.
- 정확도: 이 예제 사이트에서 시험한 결과, 새로 만든 질문 10개 중 8개는 첫 결과가, 9개는 위 3개 안에 알맞은 문서가 있었습니다. 범위 밖 질문은 걸러내려고 하지만 완벽하지 않습니다(범위 밖 4개 중 1개만 걸러냄). 사이트 안에 자주 나오는 단어가 들어 있으면 엉뚱한 문서가 나올 수 있습니다.
- 색인(`/assets/search-index.json`)에 소제목별 본문이 담겨 파일이 커집니다(이 예제에서 약 42KB에서 약 90KB). 한 절은 4000자까지만 담고, 본문 합계가 약 3MB를 넘으면 문장 찾기는 저절로 꺼집니다.
- 끄려면 설정 `krds.search.sentence`를 `false`로 씁니다(기본 켜짐). 끄면 색인에 소제목 본문이 빠집니다.

### AI로 답변 만들기(선택)

검색 결과 아래에 **AI로 답변 만들기** 패널을 둘 수 있습니다. 위 검색에서 찾은 근거 글을 바탕으로 AI가 질문에 답하고, 답에 쓴 근거 글을 링크로 보여 줍니다. **기본은 꺼져 있습니다.** 켜려면 `krds.search.answer`를 `true`로 쓰세요(위의 "문장으로 찾기"가 켜져 있어야 합니다).

- **방문자의 API 키로 방문자의 브라우저에서 제공사를 직접 부릅니다.** 이 사이트에는 서버가 없고, 키·질문·답변을 받거나 저장하지 않습니다. 비용은 방문자가 제공사에 냅니다.
- **지원하는 제공사:** OpenRouter(로그인 또는 키), OpenAI 호환 주소(OpenAI, 내 컴퓨터의 로컬 서버 등), Anthropic(Claude), Google Gemini. 모델 이름은 자주 바뀌어서 목록을 불러오거나 직접 적습니다. OpenRouter 로그인은 키를 붙여넣지 않고 OpenRouter 계정에 연결하는 방식입니다(OAuth PKCE).
- **무엇이 전송되나:** 방문자가 입력한 질문과 검색에서 찾은 근거 글(최대 약 3,000자)이 방문자가 고른 제공사로 갑니다. 패널에서 전송 대상을 보여 주고 동의 칸을 선택해야 보냅니다. **비공개 내용이 색인에 들어 있는 사이트에서는 켜지 마세요.** 근거가 없으면 제공사를 부르지 않습니다.
- **키 보관:** 기본은 메모리에만 두어 새로고침하면 사라집니다. 방문자가 "이 탭을 닫기 전까지 기억"을 고르면 이 탭의 `sessionStorage`에 두고, `localStorage`에는 제공사·모델·서버 주소 같은 비밀이 아닌 설정만 둡니다. 키 지우기 버튼이 있습니다. 키는 제공사 사이트에서 사용량 한도를 걸어 두고 쓰는 것을 권합니다.
- **고지:** 답변 위에 **AI가 생성한 답변**이라는 표시와 "틀릴 수 있다"는 안내가 붙습니다. 생성형 AI 서비스에 대한 고지 의무(인공지능기본법 등)가 사이트 운영자에게 적용되는지는 사이트마다 달라서 운영자가 확인해야 합니다.
- **CSP:** `Content-Security-Policy`를 쓰는 사이트는 `connect-src`에 쓰려는 제공사 주소(`https://openrouter.ai`, `https://api.openai.com`, `https://api.anthropic.com`, `https://generativelanguage.googleapis.com`)를 허용해야 합니다.
- **안전:** 답변은 글자로만 넣으므로 HTML이나 스크립트가 실행되지 않습니다. 근거 글 안의 문장은 지시가 아니라는 안내를 모델에 함께 보내지만, 모델이 이를 항상 지킨다고 보장할 수는 없습니다.
- **한계:** 근거는 위 검색이 고른 글이라 검색이 틀리면 답도 틀립니다. 모델이 근거를 벗어나 답할 수도 있어 근거 링크로 확인하게 했습니다. **실제 제공사 호출은 테마 저장소에서 테스트 키 없이 확인하지 못했습니다.** 요청 형식은 각 제공사의 공식 문서와 가짜 응답으로만 검증했으니, 쓰다가 문제가 있으면 이슈로 알려 주세요.

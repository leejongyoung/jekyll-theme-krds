## 태그

글의 front matter 에 `tags` 를 쓰면 글 위의 메타 정보에 태그 링크가 생기고, 링크를 누르면 태그 페이지의 해당 구역으로 이동합니다.

```yaml
---
layout: post
title: "글 제목"
tags: [접근성, 가이드]
---
```

태그 페이지는 `tags` 레이아웃으로 만듭니다. 글뿐 아니라 `tags` 가 있는 일반 페이지(이 문서처럼)도 함께 모읍니다.

```yaml
---
layout: tags
title: 태그
permalink: /tags/
---
```

## 검색

검색 페이지는 `search` 레이아웃으로 만듭니다. 만들고 나면 헤더에 **검색** 버튼이 자동으로 생깁니다.

```yaml
---
layout: search
title: 검색
permalink: /search/
search: false
---
```

- 빌드할 때 `/assets/search-index.json` 을 만들고, 브라우저에서 이 파일 하나만 읽어 검색합니다. 외부 서비스나 별도 서버가 필요 없습니다.
- 공백으로 나눈 단어가 모두 들어 있는 글을 찾습니다. 한국어는 단어 중간(예: "접근" → "접근성")도 찾습니다.
- 태그 칩으로 결과를 좁힐 수 있고, 주소(`?q=…&tag=…`)로 결과를 공유할 수 있습니다.
- 검색 대상에서 빼려면 페이지 front matter 에 `search: false` 를 씁니다.
- 일반 검색은 본문을 글마다 앞의 3000자까지만 색인합니다. `_config.yml` 의 `krds.search.max_chars` 로 바꿉니다.

### 문장으로 찾기

질문처럼 문장으로 적어도(예: "첨부 파일에 바이러스가 있는지 검사할 수 있나요?") 가까운 내용을 찾아 검색 결과 아래의 **질문과 가까운 내용**에 보여 줍니다. 단어가 모두 들어 있는 글이 없을 때, 또는 네 단어 이상의 문장일 때 나타납니다. 한두 단어만 넣는 일반 검색은 그대로입니다.

- 글의 소제목 단위로 찾아 `글 제목 › 소제목` 링크와 일치한 부분을 보여 주고, 링크를 누르면 그 소제목으로 이동합니다.
- 모델이나 외부 서비스 없이 글자 두 개씩 겹치는 정도에 희귀도를 곱해 점수를 냅니다. "…할 수 있나요?"처럼 조사와 어미가 붙어도 찾고, 새로 내려받는 파일이 없습니다.
- 태그로 좁히면 그 태그가 있는 글 안에서만 찾습니다.
- **답을 문장으로 만들어 주지는 않습니다.** 관련 있어 보이는 부분을 찾아 줄 뿐이라 정확한 답이 아닐 수 있습니다.
- 정확도: 이 예제 사이트에서 시험한 결과, 새로 만든 질문 10개 중 8개는 첫 결과가, 9개는 위 3개 안에 알맞은 문서가 있었습니다. 범위 밖 질문은 걸러내려고 하지만 완벽하지 않습니다(범위 밖 4개 중 1개만 걸러냄). 사이트 안에 자주 나오는 단어가 들어 있으면 엉뚱한 문서가 나올 수 있습니다.
- 색인(`/assets/search-index.json`)에 소제목별 본문이 담겨 파일이 커집니다(이 예제에서 약 42KB에서 약 90KB). 한 절은 4000자까지만 담고, 본문 합계가 약 3MB를 넘으면 문장 찾기는 저절로 꺼집니다.
- 끄려면 설정 `krds.search.sentence`를 `false`로 씁니다(기본 켜짐). 끄면 색인에 소제목 본문이 빠집니다.
